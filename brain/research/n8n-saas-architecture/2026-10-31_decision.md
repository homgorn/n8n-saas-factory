# Deep Research — n8n SaaS Architecture Under Licence Constraint

## Plan

Reframed decision: the user asked to "create a SaaS from n8n workflows". The underlying
question is whether the business architecture is defensible given n8n's Sustainable Use
License. The report compares N architecture options (hosted, embedded/OEM, customer-brings-own)
against the licence text, external sources, and the existing project state (1,348 docs, 9,578
chunks, 688,466 words, 11 provenance claims).

Scope: architecture + licensing, not feature-level implementation. Every claim links to
`brain/index/claims.json`. Refresh targets: OEM price confirmation, customer-self-host
legal opinion, new n8n release notes.

Risk register:
- OEM price is reported (~$50k/yr) but not confirmed by n8n pricing page — marked `unconfirmed`.
- Customer-brings-own-n8n is permitted (licence grants non-exclusive use for internal/business
  purposes) but requires the customer to have a valid n8n installation and licence of their own.
- Multi-tenant isolation relies on Supabase RLS (`brain/data/wiki.db` schema) plus per-customer
  n8n API keys — the RLS policies exist but have not been load-tested at scale.

## Findings (atomic, reusable theses)

### F-LICENCE
- Source 01: n8n Sustainable Use License (`https://github.com/n8n-io/n8n/blob/master/LICENSE.md`).
  Type: `reported`. Score: credibility 10/10 (primary source file), recency 10/10 (current main), bias 0/10 (licensor).
  Verbatim: "You may use or modify the software only for your own internal business purposes or for non-commercial or personal use. You may distribute the software or provide it to others only if you do so free of charge for non-commercial purposes."
- Source 02: Activepieces blog (`https://www.activepieces.com/blog/n8n-white-label-cost-and-what-you-can-rebrand-2026`).
  Type: `reported`. Score: 6/10 (industry blog, not n8n official), recency 10/10 (Oct 2026), bias 0/10.
  Verbatim: "The n8n OEM / Embed deployment requires a separate commercial agreement with n8n... costs roughly $50,000 annually."
- Source 03: n8n community forum (`https://community.n8n.io/t/does-anyone-have-a-rough-idea-of-how-much-an-n8n-commercial-license-would-cost-to-integrate-n8n-into-a-b2b-saas-solution-that-we-sell-to-businesses/316047`).
  Type: `reported`. Score: 7/10 (direct user report, not official pricing page), recency 10/10 (Sep 2026).
  Theme: same $50k figure.
- Source 04: n8n docs (`https://docs.n8n.io/deploy/host-n8n/deploy-as-an-oem-integration`).
  Type: `reported`. Score: 10/10 (official docs), recency 10/10.
  Verbatim: "Overview of OEM deployment — surfacing n8n's interface inside your own product's UI under an OEM agreement."

Triangulation: 2 primary sources (licence file, docs) agree on the limit; 2 industry sources agree on the OEM price; no contradictory source found. The price claim is marked `unconfirmed` — not `measured` — because no official pricing page confirms it.

### F-ARCHITECTURE
- Source: multi-tenant boilerplate (`https://community.n8n.io/t/built-a-multi-tenant-boilerplate-for-running-n8n-across-many-client-instances-siennabase/301807`).
  Type: `reported`. Pattern: webhook URL routing per tenant; credential isolation; no embedded n8n.
- Source: `brain/decisions/ADR-002-saas-architecture-under-licence.md`. Type: `inferred`.
  Reasoning: given the licence limit, the architecture must avoid hosting n8n; customer-brings-own is the only path that satisfies the limit without an OEM agreement.
- Source: `brain/scripts/analyzer.py` and `brain/research/workflow-analyses/_summary.json`.
  Type: `measured`. 12 workflow templates analysed with node counts (2-31), AI agent detection (5 agents found), complexity scores (1.5-9.0), credential inventory.

## Adversarial pass (self-critique)

1. Could the OEM price be wrong? Yes — it comes from a blog and forum, not an official quote.
   Mitigation: marked `unconfirmed` in claims.json. If it is lower, the architecture does not change.
2. Could a customer use n8n Cloud and violate the licence? Unconfirmed — the docs say the customer manages their own instance for self-hosted; for Cloud, the terms apply to the cloud subscriber, not to our product. A lawyer review is needed (recorded in claims as `unconfirmed`).
3. Is the multi-tenant isolation sufficient? RLS policies exist in the database schema but have not been load-tested. Mitigation: recorded as a risk in the ADR.
4. Could the analysis miss a node that requires a custom credential? Yes — the credential inventory only reads the `credentials` key from workflow JSON; if a node uses environment variables or a custom node not included in the master list, it will be missed. Mitigation: the `required_credentials` list is an estimate (`estimated_db_tables`), not a guarantee.
