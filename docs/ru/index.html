Лицензионное ограничение: клиент сам держит свой n8n. См. ADR-001.

Что готово и что остаётся

Каждая функция проверяется независимо от памяти агента.

Измерено-верифицировано (3 из 10)

F001 — ingestion (гейт пересобирает корпус из источника, проверяет идемпотентность) · F002 — запросы (гейт прогоняет классификатор и JSON-проверку) · F003 — анализатор (гейт гоняет анализатор на известном воркфлоу и утверждает разрешение AI-агента).

Реализовано, не проверено (7 из 10)

F004 (шаблон никогда не npm-устанавливался и не собирался) · F005 (генератор работает, но проект никогда не собирался) · F006 (MCP-конфиг есть, соединения не тестировались) · F007 (агенты определены, на пробном задании не проверялись) · F009 (smoke-тесты написаны, ни разу не запускались) · F010 (документация и сайт есть, видео не записано) · F008 (нужен работающий n8n для webhook/cron).

По правилу проекта `passes: true` ставится только после проверки. Ранний значок «9 из 10» был оптимистичным; честное число — 3.

Следующий гейт

F008 верификация: запустить n8n локально, импортировать n8n-wiki/workflows/f008-sync-workflow.json, прогнать webhook и cron. Только после этого ставить passes: true.
